Tiny KV in Go with mmap

8 min · src ↗ · go / mmap / durability

Goal: feel the LSM tradeoff instead of reading about it. Single file, stdlib only, crash-safe by fsync on commit.

Log format

Records are [keyLen|valLen|key|value|crc]. On open we scan once and rebuild the offset map. Reads are one mmap slice, writes are O(1) appends.

// pseudo — index rebuild
for off := 0; off < size; {
  k, v, n := readRecord(mmap[off:])
  index[k] = off
  off += n
}

Numbers

$ go test -bench=. -count=3
BenchmarkPut-8   412331   2891 ns/op
BenchmarkGet-8  1842211    651 ns/op
$ ls -lh test.db
12M  test.db

Fine for <100k keys. Compaction is where it gets real — that's part 2, on branch part2-compact.

  • What breaks first: sparse deletes, not writes
  • What I'd do differently: fixed-size segments sooner
